1 · What Baligo is & current status

A custom WordPress plugin that gives your travel company a private, professional hotel-quotation workspace with two faces:

🛠 Admin dashboard

Your team manages hotels, room types, seasonal IDR net rates, inclusions, policies, agents and contract imports — all through forms, no coding. Reached inside wp-admin → Baligo.

🧳 Agent portal

Approved travel agents log in, build a stay (hotel, room, dates, rooms, adults, child ages, extra beds), see USD selling prices with a full breakdown, and copy a polished quotation for WhatsApp or e-mail. Reached at /baligo/ on your website.

Current release = complete UI prototype on demo data. Every screen described in this document is implemented and clickable. All data is realistic sample data, all actions are simulated (honest “demo” notices are shown), and no server-side pricing, database, authentication or AI processing is active yet. This is exactly what was requested for this phase: static UI, not dynamic. Section 14 lists the backend work required to go live.

The interface is built with React 18 + TypeScript + Tailwind CSS + shadcn/ui, compiled by Vite, and shipped inside the plugin as ready-made files — the WordPress site needs no build tools to run it.

3 · Admin dashboard guide

Overview (dashboard home)

Key figures (hotels, room types, active agents, contracts awaiting review), a “Needs attention” queue that lists rate conflicts, expiring/expired/incomplete rates and agent approvals, the latest rate changes, recent agent activity, a seasonal-pricing health bar and quick actions. Everything links to the screen where you resolve it.

Hotels

Searchable, filterable, sortable table (status, destination). Add or edit a hotel: name, destination, country, address, star category, status (active / draft / inactive), description, amenities, inclusions and policies (check-in/out, cancellation, children, extra bed). The hotel detail page has tabs for Overview, Room types and Rates, and a “last updated by” trail.

Room Types

Every room type across all hotels, with an editor for: description, size (m²), bed type, standard and maximum occupancy (adults / children / total), extra-bed eligibility and limits, amenities, meals, and the child-policy and extra-bed-policy texts agents will see.

Supplier Rates (seasonal pricing)

Pick a hotel → room type and you get its seasons. Each seasonal rate holds: season name & dates, contract validity window, IDR net rate per night (marked Commercial — internal only), minimum stay, holiday surcharge (percent + note), age-banded child charges, extra-bed charge, inclusions and supplements. Statuses flag rates as Valid Expiring / Incomplete or Expired / Conflict. A side panel keeps the default markup, rounding rule and IDR-per-USD rate close at hand.

Rate History

A chronological audit timeline of every change — net rate, season dates, validity, surcharge, markup and exchange-rate updates — with who changed what, from which value to which, plus filterable comparison dialogs. (In this release the timeline shows sample data; the backend phase makes it automatic.)

Contract Import

The launchpad for AI imports — see section 5.

Agents

All agent accounts with status badges, a Pending approval tab, approve / reject / deactivate / reactivate flows (with confirmation dialogs), invitations, and an agent detail page with an editable profile and activity trail.

Settings

Company identity, default currency (USD), IDR-per-USD exchange rate, default markup %, rounding rule, quotation validity, date format & timezone, hotel pricing defaults (min stay, max child age), agent-portal display toggles, notification preferences and import preferences (auto-extract, require human review, duplicate strategy). Saving is validated — and in this release clearly marked as a demo action.

4 · Agent portal guide

Designed mobile-first for agents who prepare quotations for their clients.

1 · Sign in & account states

Email + password sign-in (with “forgot password” and error-state demonstrations), a Pending approval screen shown to newly registered agents, and a Deactivated account screen. Administrators approve accounts from the dashboard — until then an agent cannot proceed.

2 · Find a hotel & room

Home opens with a search launcher (destination, check-in/out, rooms, adults, children, child ages, extra beds). Results show hotel cards with inclusions and expandable room lists, each with a per-night USD price for the chosen dates. Rooms without a valid contracted rate show “Rate unavailable for your dates” with a Request-quotation action instead of a made-up price.

3 · Configure the stay

The stay screen lets the agent adjust dates (nights computed automatically), rooms, guests, child ages and extra beds. Occupancy is enforced visually — exceeding a room type’s maximum occupancy blocks pricing with a clear message. Included benefits, child policy and extra-bed policy are shown from the hotel/room configuration. A live summary panel shows the running total.

4 · Review the quotation

A full breakdown: room total per season segment (stays that cross a season show each part separately), extra beds, child charges and holiday surcharges, ending in a clear USD total. Inclusions, occupancy info and client-facing policies sit beside it. If a rate is missing, expired or unresolved, the price panel is replaced by an honest “Request quotation” action — never a fabricated price.

5 · Share it

The preview renders a polished, printable quotation document (Baligo letterhead, reference, validity dates, breakdown, policies, terms) with Copy text · WhatsApp · E-mail · Print actions. Sharing is simulated in this release; the WhatsApp/e-mail buttons demonstrate exactly where delivery will hook in.

Agents can never see supplier net rates (IDR), markup percentages, contracts, supplier names or internal notes — enforced in the interface layer and re-verified by an automated check on every build (35-point UI test suite).

5 · AI PDF contract import

Turn supplier contracts and rate sheets into structured rates — with a human always in control.

The four-step workflow

StepWhat happens
1 · UploadDrag-and-drop or browse (PDF; scanned documents supported). Simulated progress, file list with remove controls. In production the file is stored in a private, non-public folder — never a public URL.
2 · Review extractionSide-by-side source page + extracted data: hotel info, currency, room types, seasonal rates, dates, inclusions, child & extra-bed policies — each field with a confidence indicator. Unclear fields, currency mismatches (e.g. one season quoted in USD among IDR) and missing values are flagged, never guessed.
3 · Resolve issuesAn editable review table: inline edits, uncertain values highlighted, duplicate/overlap comparisons against existing rates (“new IDR 2,745,000 vs existing IDR 2,640,000”), and a resolve action per warning. Saving is blocked until conflicts are handled.
4 · Approval previewA summary of changes, remaining warnings and a required checkbox: “I have reviewed the extracted data against the source document.” Only then can the import be approved — and cancelled at any time.
Privacy by design: contract PDFs are commercially sensitive. The plan stores them outside the public uploads directory (or with deny-all rules in .htaccess/nginx), excludes them from any page caching/CDN, and shows them only to logged-in administrators. The import screens state this explicitly.

6 · AI / OCR provider & ongoing costs

This release ships the workflow UI only — no AI vendor is locked in. For the production build we recommend a two-stage pipeline: an OCR service reads the pages (including scans), then a language model structures the text into the editable review table. Indicative options:

Provider / serviceRoleIndicative cost*Notes
Google Document AI Recommended OCR + table structure ≈ US$1.50 per 1,000 pages Strong on scanned hotel rate sheets; table detection helps rate grids.
Amazon Textract OCR + forms/tables ≈ $1.50/1,000 pages (text) · ≈ $50/1,000 (forms/tables) Alternative if you prefer AWS; good accuracy on scans.
OpenAI GPT-4o mini Structuring (JSON) from OCR text ≈ $0.05–0.20 per contract Cheap, fast; pairs with any OCR.
Anthropic Claude Structuring (JSON), or direct vision extraction ≈ $0.05–0.30 per contract Handles messy scanned layouts well; direct page-image extraction possible.
Tesseract OCR (self-hosted) OCR only Free No per-page cost, but noticeably lower accuracy on scanned contracts; more manual review.

*List-price ballparks as of early 2026 — please verify current pricing on each provider’s pricing page before go-live.

Expected ongoing cost for Baligo

A typical hotel contract is 5–30 pages. At the recommended stack (Document AI + GPT-4o mini) that is roughly US$0.02–0.15 per contract. Even importing 200 contracts a month would stay under ~$10/month plus the LLM/API usage — the larger running cost is human review time, which the approval workflow is designed to make quick.

Key management: provider API keys will be stored as WordPress constants in wp-config.php (outside the database and the codebase), never in the browser, and never committed to the repository.

7 · Pricing model & worked examples

The formula

USD selling rate (per night) = IDR net rate ÷ IDR-per-USD × (1 + markup %)
                             → rounded by the configured rounding rule
                               (e.g. round up to next $1)

Worked example (demo settings: 16,395 IDR/USD, 20% markup, round up to $1):

IDR 2,050,000 ÷ 16,395 × 1.20 = $150.05  →  rounded up to $151.00 per night

These are exactly the numbers the agent screens show, so the UI, this document and the future backend engine agree on one definition.

Rules applied to every quotation

RuleHow it behaves
Per-night, season-awareEach night is priced with the season covering that date. A stay crossing seasons (e.g. 6 nights low season + 2 nights high season) shows one line per season segment in the breakdown.
Contract validityNights beyond a contract’s validity make the rate expired → “Request quotation”, no price invented.
RoomsRoom lines multiply by the number of rooms.
ChildrenPer-room age bands (e.g. 0–3.99 free, 4–11.99 a charge, 12+ adult rules) come from the seasonal rate; ages are entered per child on the agent side.
Extra bedsOnly where the room type is eligible, up to its maximum; charged per night with the configured amount.
Holiday surchargePercentage uplift on affected nights as configured per season (e.g. 21% during Nyepi week), shown as its own breakdown line.
Occupancy limitsAdults + children are checked against the room type’s maximum occupancy before any price is shown.
RoundingApplied to the final selling rate per night: none / up to $0.50 / up to $1 / nearest $1.

“Request quotation” states

Instead of guessing, the agent portal shows an explicit state and a request button when a rate is: missing (no season covers the dates), expired (contract validity passed), unresolved (conflict flagged in a contract review), when occupancy is exceeded, when the date range is invalid, or when more information is needed.

In this release the numbers come from a deterministic demo helper that implements the formula above over the mock rates — it is intentionally not wired to any persistence or server computation. The production engine (server-side PHP) implements the same formula with the real database.

9 · Security & privacy design

ConcernDesign
Net rates & contracts stay admin-onlyAgent screens never render net rates, markup, supplier names or contracts — enforced in the interface layer and re-checked by an automated grep test on every build.
Server-side authorityProduction calculations, approvals and data access run in PHP with capability checks (current_user_can()) and nonces — the browser never decides what an agent may see.
Shared databaseOne set of custom tables (hotels, rooms, seasons, rates, agents, quotations, audit log) with typed columns and indexed lookups; quotations stored per agent.
Private documentsContract PDFs stored outside the public uploads path (or deny-all rules), served only through a permission-checked PHP endpoint.
Cache exclusionThe app pages and REST endpoints are sent with no-cache for logged-in users and excluded from Hostinger/LiteSpeed caching so private pages are never cached publicly.
API keysOCR/LLM keys live as constants in wp-config.php; never in JS, never in the DB, never in the repo.
OwnershipAll accounts, licences and code are contracted to you; the plugin is self-contained under your WordPress install.

11 · Setup on Hostinger (staging first)

Install

  1. Copy the baligo folder into wp-content/plugins/ (or upload the plugin ZIP via Plugins → Add New → Upload).
  2. Activate Baligo – B2B Hotel Quotation Portal in Plugins.
  3. Open Settings → Permalinks → Save Changes once (registers /baligo/).
  4. Open wp-admin → Baligo — the dashboard loads with demo data.
  5. Visit https://your-domain/baligo/ — the agent portal loads.

Editing the front end (developers)

cd wp-content/plugins/baligo/app
npm install          # once
npm run dev          # live dev server (#/admin and #/agent routes)
npm run build        # rebuilds assets/ that WordPress serves
npm run smoke        # 35-point UI + mobile-overflow test (headless Chrome)
npm run visual       # interaction tests + screenshots → qa-screenshots/

The compiled assets/js/baligo.js and assets/css/baligo.css are part of the plugin — the live site does not need Node.

Deployment order: Hostinger staging site → sample-contract import test → your sign-off → production. Always keep a database backup before plugin updates.

14 · Roadmap to production

Phase 2 — backend integration (the “dynamic” build)

  1. Data layer: custom DB tables + REST endpoints (agents, hotels, rooms, seasons, rates, quotations, audit log) — the UI was built so every screen maps 1-to-1 to these.
  2. Auth: agent accounts on custom tables or WP users with an “agent” role; admin approval workflow; server-side password reset e-mails; session/nonce protection.
  3. Pricing engine (PHP): implements §7 server-side — per-night season lookups, child bands, extra beds, surcharges, rounding, validity and conflict checks; results stored with each quotation.
  4. AI import: Document AI (or Textract) + LLM structuring behind the Step-2 UI; private file storage; confidence + warning flags from real analysis.
  5. Sharing: real “copy”, WhatsApp deep links and e-mail dispatch (via your SMTP); optional PDF export.
  6. Hardening: capability checks, nonces, rate limiting, cache exclusions, backups.
  7. Delivery: signed plugin ZIP, source handover, staging validation with your sample contracts, short training video, bug-fix window.

15 · FAQ & troubleshooting

The /baligo/ page shows my theme’s 404.

Open Settings → Permalinks → Save Changes. This flushes WordPress’s rewrite rules and registers the portal address (done automatically on activation, but worth repeating after migrations).

The dashboard content looks squeezed inside wp-admin.

The app is designed for the full content width and renders its own sidebar next to the WP menu. Hard-refresh the page (Ctrl/Cmd + Shift + R) so the browser picks up the newest CSS/JS.

Are the prices real?

No — every figure is demo data labelled as such, generated by the documented formula over sample hotels. Nothing is stored or sent. This is intentional for the UI phase.

Can agents change rates?

No. The agent portal is read-only for pricing: agents compose and share quotations; all rate management happens in wp-admin. Server-side capability checks will enforce this in the production build.

What happens when a contract expires?

Stays touching expired dates lose their price and show the honest Request quotation state; the admin dashboard lists expiring rates in “Needs attention” before it happens.
